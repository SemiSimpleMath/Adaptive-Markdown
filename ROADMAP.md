# Roadmap

What's planned, what's being worked on, what's still aspirational. Ordered roughly by expected ship order, not a commitment. Open a GitHub issue if you want to push on or contribute any of these — it helps avoid duplicate work.

## Active backlog

Things we've designed and intend to ship in the next iteration or two.

### Codex runtime parity

Codex mode landed experimental in v0.1. Bringing it to feature parity with Claude mode means closing several gaps:

- **Per-edit snapshot/patch granularity.** Today Codex snapshots once per changed file per turn; Claude does this per `Edit` tool call via SDK hooks. If/when Codex CLI exposes pre/post tool hooks, the adapter should match Claude's granularity.
- **Per-turn budget cap.** Claude caps spending at `MAX_BUDGET_USD` per turn. Codex has no equivalent — a wall-clock or token-count cap belongs in the adapter to prevent runaway turns.
- **Stable JSONL event parsing.** `codex_runtime._jsonl_to_event` heuristically maps event types and will likely break if Codex CLI changes its output schema. Either pin to a known-good CLI version or fall back gracefully on unrecognized event types.
- **Agent screenshot tool for visual iteration.** Visual edits (figures, animations, page-wide CSS, embedded UI) are currently the only thing the agent can't verify on its own — it writes code and waits for the human to say "the snake is invisible." Adding a `tools/screenshot_doc.py` the agent can invoke after a visual change, plus skill guidance on when to use it, would close the perception loop. Two phases: (1) reuse the existing monitor-capture script; agent reads via the existing image-aware `Read` tool. (2) `html2canvas` inside the iframe so the agent sees only the doc, not the whole screen — smaller context, no chat-panel feedback loop, no incidental privacy leak. Codex-side support depends on whether the model has vision in CLI exec mode and whether Codex's read tool surfaces image bytes; investigate.
- **Validator retry-loop parity (deferred — has trigger).** Claude side runs `validators.py` in `PostToolUse`, reverts the file on JS/CSS/SVG errors, and pushes the validator errors back into the SDK's `additionalContext` so the agent immediately retries with structured feedback. Codex's existing per-turn write-path validator can call the same `validators.py` and revert, but cannot feed errors *back into the agent's tool-use loop* — Codex's JSONL stream is one-way, so the agent just sees a chat-side system message after the turn ends and has to be re-prompted. Closing this gap means either (a) restarting Codex with a constructed prompt that includes the validator errors, or (b) waiting for Codex CLI to expose a structured per-tool-call feedback channel. **Trigger to revisit:** Claude-side validator has been stable for 30 days *or* a Codex-using contributor opens an issue requesting it, whichever comes first.

### Authoring + reading

- **Asset drop.** Drop an image / data file / audio into the doc area and it lands in `docs/<slug>/assets/`; the agent gets told the file is there and can reference it as `assets/<file>` in the doc body. Companion to the doc-as-folder layout — `assets/` is already the canonical place for materials, this just makes the drop UX wire it up.
- **Component library / reusable snippets.** When the agent produces something good in one doc (a snake game, a working clock, a dark-mode toggle, a stopwatch, a specific math figure), the user can save it and reuse it later in any doc — *"save this as `snake-game`"* in chat, then *"insert the snake game"* anywhere else. Storage layer: a `components/` directory at the project root, one file per component, each file is itself a valid mini adaptive-markdown doc (frontmatter with name/intent/tags/provenance + body = HTML blocks + embedded `<script>`). Key nuance: because each saved component is plain markdown, the agent can *adapt on insertion* — *"insert the snake game but in red,"* *"insert the clock with Roman numerals"* — so the unit is a seed, not a frozen widget. Open issues to settle when building: ID uniquification on insert (two copies of `<canvas id="snake-game">` collide); self-containment metadata (a snake game is self-contained, a page-walking falling-letters effect isn't — components should declare scope); CSS class namespacing to prevent style leaks; later, a viewer-side Components panel for browse + drag-insert (chat is enough for v0). Sharing is free — a `components/` dir is just files, trivially zip-able, git-able.
- **Variant blocks for audience presets.** Mark a block as variant-bearing and the agent emits sibling `<section class="variant" data-audience="novice|expert|...">` blocks. Viewer renders a tab strip; reader picks a default audience.
- **Pending changes (review-before-accept).** Toggle a viewer mode where the agent writes proposed edits to a `docs/<slug>/pending.json` sidecar; viewer overlays accept/reject UI on each proposed change. `current.md` isn't touched until accept.
- **Annotation overlay.** A non-destructive layer for reader highlights, agent-marked dependencies ("blocks that depend on assumption X"), and query results. Sidecar JSON, toggleable in the viewer.

### Quality-of-life

- **Doc-list watchdog.** Today the viewer's doc dropdown only refreshes when files are added via the upload endpoint. A filesystem watcher would broadcast updates when `.md` files appear or disappear externally (git pull, drag in a file manager, etc.).
- **First-run setup card.** If no API key is visible at backend start, the viewer prompts for one rather than failing on the first chat turn.
- **"Save as baseline" action.** Today, manually-restored content in `docs/<slug>/current.md` (via `git checkout docs/<slug>/baseline.md`, paste from `keepers/`, an editor edit, etc.) isn't propagated to `baseline.md`. The next Reset jumps back to the original baseline, surprising the user. A small endpoint + viewer button — *"set current state as baseline"* — would overwrite `baseline.md` with the working copy. Until shipped, the workflow is `cp docs/<slug>/current.md docs/<slug>/baseline.md` from the command line.
- **Byte-exact snapshots (`save_snapshot` line-ending fix).** `save_snapshot` currently uses `Path.write_text(...)` with default `newline=None`, which on Windows translates `\n` → `\r\n` on write. Combined with `read_text(...)` doing the inverse on the way in, the captured snapshot may not byte-match the source working copy. Doesn't affect content equality (universal-newline comparisons all match), but causes spurious size deltas and `doc_changed` flicker after Reset/Restore. Fix: switch `save_snapshot` to `write_bytes` (or `write_text(..., newline="")`) and have callers pass through `read_bytes` where appropriate so the snapshot is a byte-for-byte copy of the source.

## Planned

Designed at a sketch level, not actively being implemented.

### Computation

- **In-browser Python via Pyodide.** A reserved `<div class="computation" data-lang="python">…</div>` block whose body the viewer executes in a Pyodide worker. SymPy + matplotlib available; figures with parameters can be re-run live in the doc. Adds ~6MB to first load — lazily fetched only when a doc contains a computation block.

### Multi-document

- **Cross-doc references and dependency graph.** Anchor links resolve across documents (`[Rolle's theorem](rolle-paper#main)`); the viewer surfaces backlinks (which docs reference this theorem) and a dependency-graph view (what assumptions a result depends on, traversed through links). Useful when you're working on a doc that builds on another doc you've already authored — the system tells you what cites it.
- **Browser-only deployment.** A single-file `am.html` bundling parser + viewer + agent loop calling the model API directly from JS. Loses local filesystem access; gains "share a URL, the recipient tries it in 30 seconds." Useful as the entry-point demo.

### Import

- **LaTeX / Pandoc-fed import hardening.** Today the one-shot converter handles .tex/.txt/.rst/.org with the agent's help. Turning that into a proper `import-tex` skill the agent invokes from chat would give wider AMS-TeX dialect support, better equation conversion, and let the agent reach for it when a `.tex` drop needs more than the simple flow.
- **PDF import.** Hard problem — math reconstruction from PDF glyph runs is the trap. Probably staged: when a `.tex` source for the PDF is available (e.g. via the publisher / preprint host), fetch and import that first; fall back to a text-extraction pipeline for genuinely PDF-only inputs.
- **Chat-log → adaptive markdown.** Take a Slack / ChatGPT / design-review export and produce a structured doc with the substantive points extracted and the chronological log preserved as provenance.

## Directional

Likely correct, far from ready, no committed plan.

- **Lean verification.** Formal statements live alongside informal prose (`[Lean: theorem rolle : ...]`); Lean checks them; the agent keeps the formal statement in sync as the prose evolves. Proof bodies stay as `sorry`. The framing is "AI keeps the formal statement honest," not "AI proves your theorems."
- **Hosted multi-user mode.** Real-time collab, persistent storage, version-graph hosting, audit trail. Likely a separate product on top of the same format.
- **Multi-agent / multi-writer concurrency.** Real CRDT or 3-way merge for simultaneous editors. Today's optimistic-apply substrate handles solo authoring with a single agent; this is the future when a doc has multiple human + agent contributors.

## Open design questions

Decisions to make when the relevant feature lands. Captured here so contributors know they're not settled.

- **Snapshot semantics: pre-edit vs. post-edit (vs. HEAD-pointer).** Today the substrate is *pre-edit*: the `PreToolUse` hook captures the doc's state right before each agent `Edit`/`Write`. Snap N = "state before edit N." This creates an asymmetry: the *result* of the most recent edit lives only in the working copy, not in any snap. Destructive UI actions (`/reset`, `/undo`, `/restore_snapshot`) used to silently destroy that latest state. **Mitigation in place:** each restore handler captures the current working copy as a safety snap before overwriting, so the History panel can always recover the just-lost state. Known v0 limitation: with safety snaps in `/undo`, double-clicking Undo can read the just-taken safety snap as the new "newest" and produce a "redo" instead of a deeper undo. Accepted as the rare edge case; the common case (single Reset/Undo destroying current state without recourse) is fixed. **Longer-term:** either move the snapshot to `PostToolUse` (snap N = "state after edit N"; latest snap always equals working copy), or introduce a HEAD-pointer model with proper undo/redo (snaps are immutable history; HEAD moves through them; "current state" is a derived concept). The latter is the correct answer for multi-writer work but isn't blocking today.
- **Sub-block diff granularity.** Pending-changes review and any future multi-writer merge needs a notion of "what changed inside this block." Today we have full-block before/after. Question for that feature: do we compute character-level deltas, or is whole-block replacement enough?
- **Anchor ID uniqueness across docs.** With multi-doc workspaces, do `{#rolle}` anchors need to be globally unique, or namespaced by doc slug? Probably the latter — `docs/rolle-paper/current.md#rolle` is the natural cross-doc reference shape.
- **Frozen / republished doc lifecycle.** When a doc is intentionally locked (a finished version distributed for reading), do new tracking IDs mint in the frozen copy, or does a fork happen? Relevant once any "this version is final" UI exists.

## Recently shipped

For context on pace.

- **Structured content moved to HTML blocks.** Retired the `:::` directive grammar entirely in favor of `<aside class="note">`, `<figure>`, `<section class="theorem">`, `<div class="pinned">`. CommonMark passes HTML blocks through verbatim, CSS targets class names directly. Whole categories of bugs (markdown-it-attrs intercepting `{...}`, parseDirectiveInfo regex edge cases, directive grammar vs HTML grammar) vanish. Renderer shrank by ~170 LoC; the validator dropped its directive checks; the skill collapsed two equivalent representations (heading-form vs directive-form theorems) into one. Browser-smoke gained a `scenario_html_block_structured_content` to lock the patterns.
- **Doc-as-folder layout.** `docs/<slug>/baseline.md` (history-0, tracked), `current.md` (working copy, gitignored), `snaps/` (pre-edit captures, gitignored), `assets/` (materials). Replaces the old `examples/<name>.md` + `.history/<stem>/` split. `.gitignore` is now a structural invariant: only the three ship-with docs' baselines (plus optional provenance + assets) can ever land in commits. WebSocket protocol switched to slug-based (`{doc: "intro"}` instead of file paths). The patches sidecar was retired — diffs can be recomputed from snapshots later if a review pipeline ever needs them.
- **Insert-here position selection.** Clicking in the gap between blocks (rather than on a block) sets an insertion point; the chat preamble names the surrounding blocks and tells the agent to anchor its Edit on one of them. The viewer paints a slim horizontal marker at the chosen gap. Removes "agent guesses from prose" as a positional error mode.
- **Iframe runtime: morphdom + per-script cleanup registry.** Doc updates now diff into the iframe in place — scroll position, in-progress canvas animations, attached listeners all survive edits. `window.__doc.cleanup(fn)` tracks teardowns per-script via a WeakMap; cleanups fire only when the registering script is removed/replaced, so unchanged animations keep running across sibling edits.
- **Doc inlined in chat preamble.** The active doc (up to 50 KB) is read once per turn and injected into the agent's context between fence markers. Saves a `Read` tool round-trip per turn; amortized by prompt caching from turn 2 on. Skill instructs the agent not to `Read` the file unless they've edited it themselves since the preamble.
- **Validator hardened.** JS check switched from `new Function` (function-body grammar) to `node --check` (real script grammar, with line + caret in errors). Markdown code spans and fenced blocks are masked before tag extraction so `<script>` mentioned in prose backticks doesn't false-positive. UTF-8 forced on the subprocess pipe (no more cp1252 crashes on math characters). Server-side log prints the full multi-line error so the operator can see what the agent saw. Three-strike retry cap — after 3 consecutive validation failures on the same file, the loop is durably broken and the agent is told to stop and report.
- **Skill merge.** Side-by-side merge of the AM and AMV3 skills into one tighter, accurate spec covering: how the agent receives context (active doc, focused block, insertion point), what happens on Edit (validator + EDIT REJECTED + retry cap), the iframe runtime inventory (KaTeX, morphdom, `__doc.cleanup`), the cleanup-registry pattern, and the HTML-block conventions for structured content. The `.agents/` mirror auto-syncs at backend boot.
- **UTF-8 launcher + SIGINT watchdog (`start.py`).** Respawns Python with `PYTHONUTF8=1` before any I/O initialises so the Claude SDK's subprocess pipes don't choke on non-Latin-1 characters (`ε`, `π`, `⟹`). Force-exits 3s after Ctrl+C if aiohttp's IOCP cleanup hangs on Windows.
- **Security pass** — iframe sandbox dropped `allow-same-origin` (null-origin doc context, can't read parent or backend); `serve_static` allowlisted to favicon + `docs/<slug>/{current,baseline}.md` only (no more `.env` exposure); `Origin` validation on WS + POST routes; drop-to-convert preview dialog (user sees the first 2KB before the agent does); upload blocklist of executable/binary extensions + NUL-byte guard; Claude's `Bash` and `WebFetch` removed from `allowed_tools` + denied in `.claude/settings.json`; path-validated `pre_tool_use_hook` rejects Claude writes outside `docs/<slug>/current.md`; SKILL.md gained a "Security boundaries" section + the `.agents/` mirror auto-syncs at startup; Codex runtime got a post-turn write-path validator (revert-from-snapshot for any modification to a protected file, with chat warning) and explicit `network_access=false` override. Real-browser + real-API test harnesses make future regressions catchable in <60s — 42 browser-smoke scenarios currently.
- **Codex provider work** — skill injection, chat history replay, substrate parity (snapshots + alias bookkeeping at per-turn granularity), `start.py` launcher with persistence, model-not-supported auto-retry, activity strip mapping.
- **Provider runtime abstraction** — `agent_runtime/` registry, Protocol-based seam, Codex CLI adapter (experimental).
- **v0.1 public release** — adaptive reading (translate / restyle / expand); live in-place DOM patching; click-to-focus + multi-select; version history with restore; multi-view tabs (Doc / Graph / Source / LaTeX / Print); figure programs (canvas / SVG / Desmos); KaTeX math with `\begin{aligned}` rule; AMS-TeX importer; single-file browser deployment; per-doc model selector.
